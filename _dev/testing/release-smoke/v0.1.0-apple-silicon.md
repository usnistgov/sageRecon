This is the RECORD. Do not re-derive it.

- Archive: `recon-apple-silicon.zip` from the v0.1.0 release, downloaded in Safari
- Binary: `recon 0.1.0`, provenance `07f2f87` (the tagged commit)
- Input: `2019-4-9_909c_0311.mzML.gz` (serum) + UniProt human canonical 2023_05
- Command: `./recon run <mzml> <fasta> --enzyme trypsin --output smoke`
- **Result: COMPLETED in 79.5 s** (Pass-1 Sage 51.0 s + Pass-2 Sage 5.2 s + recon 23.4 s)

## What it proved

The archive is self-sufficient for the SEARCH path. No Rust, no repo, no Sage
binary, no `unimod.xml` on the command line. Both Sage passes ran in process,
both reports were written.

## What it FOUND — three defects CI could not catch

### 1. ⚠ RELEASE-BLOCKING: the curated mod list is read from a repo path

```
WARN recon] curated mod list not loaded, recommendations omitted: failed to read
curated mod file: reference-notes/metaMorpheusMods/Mods.txt: No such file or
directory (os error 2)
```

`main.rs` did `PathBuf::from("reference-notes/metaMorpheusMods")` — a path
relative to the WORKING DIRECTORY. That resolves inside a repo checkout and
nowhere else. **Every downloaded copy of v0.1.0 silently omits the tier
recommendations**, which are the thing the tool exists to produce. It warns and
continues, so the report still looks complete.

This is exactly the "path assumption" failure predicted before the test.

### 2. Gatekeeper KILLS the binary; it does not show a dialog

```
$ xattr -p com.apple.quarantine ./recon
0083;6a98a46a;Safari;249AFC90-7616-4EE8-8909-9112A284F37F
$ ./recon --version
zsh: killed     ./recon --version
```

On Apple Silicon an unsigned, quarantined binary is SIGKILLed. There is no
"unidentified developer" prompt and no right-click-Open path from the terminal.
`xattr -d com.apple.quarantine ./recon` fixes it, after which it runs normally.
The README said a dialog appears; that was wrong and is corrected.

### 3. Two stale strings in user-visible output

- The MS1 line reads `median |error| 11208.77 ppm, 95th percentile 123190.45 ppm`.
  That is not a mass accuracy. In an OPEN search the precursor delta carries the
  modification mass, so a ppm summary over all PSMs is meaningless. The honest
  number is in the self-calibrated block below it (+2.42 ppm bias, MAD 0.48).
  Printing it under a "MASS ACCURACY" heading reads as a bug to a user.
- The same block says "Sage v0.14.x reports both columns as |error|". The pinned
  Sage is **0.15.0-beta.2**.
